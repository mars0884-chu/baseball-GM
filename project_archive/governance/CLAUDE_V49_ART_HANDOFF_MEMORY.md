# 《決勝GM》v49 美術架構與 Claude 修改需求摘要

> 文件用途：交給 Claude 閱讀，用於 v49 程式完成與美術接口準備。  
> 建立日期：2026-07-23  
> 重要狀態：v48只供參考，不要把正式美術導入v48；下一階段以產品擁有者提供的v49為準。

## 1. 不可違反的邊界

1. 遊戲規則、數值、機率、模擬、存檔語意、功能流程與核心架構不得因美術改造而改變。
2. Codex只製作美術資產、視覺規格、命名提案、UI/UX規格與交接文件，不編寫遊戲程式。
3. Claude負責所有程式接線、資料文字替換、升級鏈、測試與封裝。
4. 允許Claude依定案文件替換：
   - 遊戲名稱。
   - 玩家本國名稱。
   - 球隊名稱。
   - 隊色。
   - 與上述內容直接相關的顯示文字。
5. 資產缺失、主題包載入失敗或舊存檔缺少美術欄位時，遊戲仍必須完整可玩。
6. 美術程式不得消耗或改變遊戲共用亂數序列。

## 4. 世界與球隊結構

- 完全架空的亞洲職棒聯盟，以台灣為主要靈感。
- 各隊可帶有台灣、日本、韓國等亞洲地方文化，並參考美國職棒呈現方式。
- 20隊組成：
  - 8隊城市型。
  - 6隊企業型。
  - 6隊概念型。
- 隊名參考台灣、美國、日本、韓國職棒命名方式。
- 禁止玄幻、仙俠、魔法與過度空泛隊名。
- 每隊可有獨立隊色、條紋、深色、淺色與城市版球衣。
- 主場通常白色；客場可用淺藍、灰色或核准的隊色。

## 5. 國家與旗幟

- 總數維持40國：
  - 20個真實國家。
  - 20個架空國家，包含海嶺共和國。
- 真實國旗必須正確。
- 台灣必須使用正確的中華民國國旗，不得用錯旗或用架空旗替代。
- 架空國家可影射亞洲、美洲、歐洲等棒球文化，但不得直接冒充真實國家。
- 國名、旗幟與文化清單將由Codex後續提案，產品擁有者拍板。

## 6. 組合式球員肖像需求

目的：支援約1200名現役球員及百年流程持續生成的新秀，避免準備上千張完整圖片。

Claude需要提供的顯示架構：

1. 每位球員必須有固定外觀種子，例如`appearanceSeed`。
2. 種子須由不可變身份資料建立或第一次生成後存入球員資料。
3. 同一球員跨畫面、存讀檔、交易與退休後維持同一張臉。
4. 轉隊時只替換帽子、球衣及隊色層，臉型身份不得改變。
5. 不得使用遊戲共用`Math.random`或任何會影響模擬結果的RNG。
6. 舊存檔若沒有外觀種子，採惰性補值並持久化。
7. 建議圖層：
   - 膚色。
   - 臉型。
   - 眼睛／眉毛。
   - 鼻嘴。
   - 髮型／鬍型。
   - 表情。
   - 帽子。
   - 球衣／職務服裝。
   - 道具與狀態小標記。
8. 需要可快取的64px與128px輸出，避免名單畫面重複合成造成效能問題。
9. Codex後續提供圖層資產、索引與組合限制；Claude只負責穩定顯示與資料接線。

## 7. v48已知美術接口與v49需確認事項

v48已有：

- `00-theme.js`
- 95個語意圖示。
- 18個美術槽位。
- `applyThemePack(pack)`。
- `loadThemePackFromJSON(text)`。
- `playerPhotos[playerId]`與`_default`。
- 六角雷達圖四個配色槽。

v48已知不足：

1. 雖有`loadThemePackFromJSON`，未確認UI中有真正可操作的主題包匯入入口。
2. `team.logo`看起來是單一資產槽，不足以支援20隊獨立隊徽。
3. `playerPhotos`以完整圖片對應，不足以支援組合式肖像。
4. 18個槽位不足以表達20隊隊色、球衣、國旗、聯盟品牌與不同卡片狀態。
5. 正式官方美術包如何預設載入、持久化、回退與單檔內嵌尚未定案。

Claude在v49需回覆／補齊：

- 是否保留`applyThemePack`相容介面。
- 官方主題包的自動載入時機。
- 設定頁是否提供JSON匯入、重設與匯出。
- 主題設定是否跨存檔共用，還是每存檔獨立。
- 每隊logo、帽徽、球衣、主輔色的穩定teamId映射。
- 每國國旗與國家視覺的穩定countryId映射。
- 組合式肖像渲染入口與快取策略。
- 單檔HTML的資產內嵌方式。

## 8. 建議v49美術資料結構

以下是資料需求，不限定Claude必須使用相同程式名稱：

```text
officialArtPack
├─ brand
│  ├─ gameLogo
│  ├─ leagueLogo
│  └─ palette
├─ teams[teamId]
│  ├─ logo
│  ├─ capMark
│  ├─ primaryColor
│  ├─ secondaryColor
│  ├─ homeUniform
│  ├─ awayUniform
│  └─ cityUniform
├─ nations[countryId]
│  ├─ flag
│  └─ palette
├─ portraits
│  ├─ layers
│  ├─ rules
│  └─ rendererConfig
├─ icons[semanticName]
├─ screens[screenName]
├─ buttons[state]
└─ cards[type]
```

資料層只保存穩定ID與外觀種子；圖片內容與遊戲數值保持解耦。

## 9. UI/UX視覺要求

最高UI參考：

`formal_overview_v03/01_CANONICAL_character_ui_reference.png`

六個主要畫面：

1. 主控台。
2. 財務。
3. 名單。
4. 交易。
5. 教練。
6. 郵件。

要求：

- 白色或極淺色資料卡維持長時間閱讀性。
- 藍色作為主要導航與結構色。
- 綠色表示正向、確認、成長或可用狀態。
- 粉紅表示焦點、特殊事件或品牌強調，不等同危險。
- 危險與刪除仍使用獨立紅色。
- 墨藍粗邊框、硬邊陰影、適度圓角。
- 背景可有港灣球場與地方文化，但不得降低表格對比。
- 手機操作區建議至少44×44 CSS px。
- 不改變現有功能流程與資訊內容；需要重排時由Claude維持原事件處理與資料來源。

## 11. 驗收條件

- 未導入美術包時，遊戲仍可完整啟動與遊玩。
- 導入美術包後，只改變外觀與核准的名稱／隊色顯示。
- 相同存檔在套入美術前後，所有數值、賽果與模擬行為保持一致。
- 不新增美術相關RNG對模擬序列的干擾。
- 20隊與40國資產不得錯配。
- 台灣國旗正確。
- 角色在64px仍能辨認，且符合簡化圖標人物風格。
- 模組版與整合單檔版視覺一致。
- PWA、離線模式與資產缺失回退皆正常。
- 原始v49檔案與美術交付包須有SHA-256比對清單。

## 12. Codex收到v49後的流程

1. 只讀解壓與盤點v49。
2. 對照v48，確認美術接口、畫面與ID是否改變。
3. 閱讀Claude提供的v49摘要與美術接口規格。
4. 若接口不足，先列出缺口交給Claude修正，不自行改程式。
5. 接口確認後，依已核准總覽製作：
   - 20隊完整品牌。
   - 20個架空國家。
   - 組合式肖像零件。
   - 95個以上語意圖示。
   - 六大畫面背景。
   - 按鍵、卡片、雷達圖與事件資產。
6. 產出主題包、資產清單、美術規範與Claude導入文件。
7. Claude負責正式接線、測試及三件套交付。
