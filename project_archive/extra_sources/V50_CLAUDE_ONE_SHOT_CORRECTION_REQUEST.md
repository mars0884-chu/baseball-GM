# 《決勝GM》V50 一次性完整修正要求

> 目的：請 Claude 在同一輪一次修完所有已知缺口，完整測試後重新交付；禁止只交差異檔或補丁。

## 一、這一輪必須修正的程式缺陷

### 1. 主客場球衣必須端到端接通

- 不要再依賴沒有呼叫端設定的 `optPlayer._portraitAway`。
- 改成明確的肖像 context，例如 `{ player, teamId, isAway }`。
- 比賽與會顯示比賽情境肖像的 UI 必須依實際主客場傳入 `isAway`。
- 非比賽情境必須定義固定且一致的預設球衣，並寫進規格。
- 肖像快取鍵必須包含 `playerId`、`size`、`teamId`、主客場狀態；轉隊或切換主客場不得顯示舊快取。

### 2. Theme pack 驗證必須真正完成

- 圖片欄位必須驗證允許的來源格式，而不只是 `typeof === "string"`。
- 明確定義並驗證允許的 team 欄位白名單。
- 未知 teamId、未知圖層欄位、錯誤圖片 URI、錯誤色彩格式都要產生清楚警告。
- `rendererConfig.layerOrder` 必須驗證：
  - 必須是陣列。
  - 每一項必須是允許的圖層名稱。
  - 不得有重複項。
  - 必要圖層不得缺少。
- 保持「警告但不阻擋載入」的既定策略，但 `valid` 與 `warnings` 的語意要在文件中說清楚。

### 3. `cityUniform` 規格必須一致

- 既定決策是取消第三套城市版，因此正式 schema、範例與文件不得再宣稱遊戲會選用 `cityUniform`。
- 為向後相容，可接受舊主題包帶有 `cityUniform`，但應忽略並警告已停用。
- 正式使用欄位只保留 `homeUniform` 與 `awayUniform`；若客場素材缺失，可回退主場素材。

## 二、這一輪必須補齊的測試

- 主場情境使用 `homeUniform`。
- 客場情境使用 `awayUniform`。
- 客場素材缺失時回退 `homeUniform`。
- 同一球員主客場切換不會命中錯誤快取。
- 球員轉隊後不會命中舊球隊肖像快取。
- 合法圖片 URI 通過。
- 非法圖片 URI 產生警告。
- 未知 team 圖層欄位產生警告。
- 非陣列、未知項、重複項、缺必要層的 `layerOrder` 都產生警告。
- 舊主題包的 `cityUniform` 相容處理有測試。
- 全部新增測試併入正式 `test_regression.js`，不得只提供臨時測試腳本。
- 重跑並回報：
  - 完整回歸測試，0 失敗。
  - 一般模式 15 年 smoke。
  - 純 GM 模式 15 年 smoke。
  - 整合單檔自驗。
