# 《決勝GM》v49 美術接口缺口清單

> 狀態：Codex 只讀盤點  
> 日期：2026-07-24  
> 原則：本文件只列出需要 Claude 確認或修改的接口，不修改遊戲規則、數值、流程或原始程式。

## 結論

v49 已具備品牌、國旗、隊色、隊徽、主題槽位與組合肖像的基本接口；40 國可依穩定 `countryId` 安全製作。  
20 隊正式美術與組合肖像仍有 3 個必須先釐清的接口問題，其中「隊名與 teamId 的關係」會直接造成隊徽錯配，屬於阻擋正式導入的 P0 問題。

## 缺口

| 優先級 | 問題 | 目前行為 | 美術風險 | 請 Claude 處理 |
|---|---|---|---|---|
| P0 | 隊名未穩定綁定 `teamId` | `CITY_NAMES` 與 `MASCOTS` 每次開局各自洗牌，再依序配給 `T0`～`T19` | 固定綁在 `T1` 的虎徽，下個存檔可能配到白鯨或其他隊名 | 在新遊戲建立時採固定 `teamId → 正式隊名` 對照；若需保留隨機聯盟，主題包資產應改以穩定品牌 ID 綁定並將該 ID 寫入存檔 |
| P0 | 玩家隊 `T0` 可自由命名，但美術固定 | 開局文字會覆蓋 `T0.name`，隊徽、帽子與球衣仍固定取 `teams.T0` | 自訂隊名可能與固定視覺完全不符 | 三選一：限制為正式 T0 品牌、讓玩家選 20 隊之一、或新增玩家隊品牌選擇／自訂美術入口 |
| P0 | `capMark` 的資料名稱與實際渲染契約不一致 | `compositePortrait()` 將 `capMark` 當作完整 64/128 方形圖層覆蓋；沒有獨立帽型底層與帽徽定位 | 若只交付帽徽，畫面只會疊一枚漂浮標誌；若交付完整帽子，欄位名稱會誤導後續維護 | 明確定義 `capMark` 為「完整帽子透明圖層」，或拆成 `capBase`＋`capMark` 並提供定位規則 |
| P1 | 肖像圖層沒有尺寸／錨點規格 | 所有圖層以 `top:0; left:0; width/height:100%; object-fit:cover` 疊加 | 各批次素材若畫布、頭部中心或安全區不同會錯位 | 固定母版畫布（建議 256×256）、頭頂／臉心／領口錨點與 64/128 輸出測試規格 |
| P1 | 肖像疊放順序固定且 `rendererConfig` 未使用 | 順序為 skin → face → eyes → nose → hair → beard → cap → uniform | 球衣最後繪製，若透明區不精準可能蓋住下巴與手部；無法由設定調整 | 確認正式 z-order，或讓 `rendererConfig.layerOrder` 生效 |
| P1 | 大型官方包無法可靠持久化 | 程式嘗試將完整 data URI JSON 寫入約 5MB 的 `localStorage`，失敗後只保留 meta | 20 隊、40 國與肖像圖層完成後必然遠大於一般容量，重新開機可能失去手動匯入包 | 官方包應隨單檔內嵌；外部自訂包改用 IndexedDB／Cache Storage，或在 UI 明示「本次工作階段」 |
| P1 | 圖片 URI 與 SVG 內容未做格式驗證 | `src` 直接插入 HTML，`loadThemePackFromJSON()` 只驗證 JSON 可解析 | 錯誤欄位不會立即指出，可能在畫面中靜默破圖 | 加入 schema 與必要欄位驗證，至少回報 teamId、countryId、圖層名稱與 URI 格式 |
| P2 | 隊徽、國旗的替代文字固定為空 | `themeTeamLogo()`、`themeNationFlag()` 產生 `alt=""` | 純圖示情境對輔助技術沒有名稱 | 若旁邊已有可見文字可保留空 alt；獨立出現時由呼叫端提供名稱 |

## 可以立即製作、不受阻擋的項目

- 聯盟品牌 SVG／PNG 與色票。
- 海嶺共和國正式國旗。
- 其餘 39 國旗：真實國旗按正式比例；架空國旗按 countryId 固定。
- 26 個 CSS 槽位的色彩、紋理與背景概念。
- 97 個語意圖示的視覺規範與 SVG 圖示。
- 20 隊品牌提案與配色板，但在 P0 解決前不綁入正式 `T0`～`T19` 主題包。
- 肖像零件的視覺探索，但正式切圖需先確認畫布與錨點。

## 建議驗收回覆

Claude 回覆以下四點後，即可開始正式資產切圖與 JSON 組包：

1. 20 隊是否改為固定隊名，以及固定對照表由誰提供。
2. `T0` 自訂隊名的正式產品決策。
3. `capMark` 是帽徽或完整帽子圖層。
4. 肖像母版尺寸、錨點與正式 z-order。
